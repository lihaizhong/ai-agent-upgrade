# 提示词工程指南

提示词工程（Prompt Engineering）是设计和优化输入提示（Prompt）以获得大语言模型（LLM）最佳输出的技术。它是与 LLM 交互的核心技能，直接影响模型的性能和应用效果。

## 提示词的基本结构

一个完整的提示词通常包含以下部分：

### 1. 角色定义（Role）

为模型设定一个特定的角色，引导模型以相应的专业视角回答问题：

```
你是一位资深的数据科学家，拥有 10 年的机器学习实战经验。
```

### 2. 任务描述（Task）

清晰地描述需要模型完成的具体任务：

```
请分析以下销售数据，找出销量下降的可能原因，并提出改进建议。
```

### 3. 上下文信息（Context）

提供必要的背景信息，帮助模型更好地理解任务：

```
背景：我们是一家电商公司，主要销售电子产品。最近三个月销量持续下滑。
```

### 4. 输入数据（Input Data）

提供模型需要处理的具体数据：

```
数据：
月份    销售额（万元）
1月     150
2月     145
3月     120
4月     110
```

### 5. 输出要求（Output Requirements）

明确指定输出的格式、长度、风格等要求：

```
要求：
1. 列出至少 3 个可能原因
2. 每个原因配一个具体的改进建议
3. 使用 Markdown 格式输出
4. 总字数控制在 500 字以内
```

### 6. 约束条件（Constraints）

设定模型必须遵守的限制：

```
约束：
- 不要建议增加广告预算
- 基于提供的数据进行分析，不要编造数据
```

## 提示词设计原则

### 清晰具体（Be Specific）

模糊："写一篇关于猫的文章"

清晰："写一篇 300 字的科普文章，介绍家猫的驯化历史，面向 10-12 岁的儿童，使用生动的比喻"

### 提供示例（Provide Examples）

通过示例展示期望的输出格式和风格：

```
请将以下句子转换为正式语气：

示例：
输入："这个方案不行，得换个思路。"
输出："经评估，当前方案存在不足，建议调整策略方向。"

现在请转换：
输入："[用户输入]"
输出：
```

### 分解复杂任务（Break Down Complex Tasks）

将复杂任务分解为多个简单步骤：

```
请按以下步骤分析这段代码：

步骤 1：识别代码的功能和目的
步骤 2：列出使用的关键算法或数据结构
步骤 3：分析代码的时间复杂度和空间复杂度
步骤 4：指出潜在的 bug 或优化点
步骤 5：给出改进后的代码

代码：
[代码内容]
```

### 使用分隔符（Use Delimiters）

使用 XML 标签、三重引号等分隔不同部分：

```
请总结以下文章的主要观点：

<article>
[文章内容]
</article>

要求：
- 列出 3-5 个主要观点
- 每个观点不超过 20 字
```

### 指定输出格式（Specify Output Format）

明确要求 JSON、Markdown、表格等格式：

```
请将以下信息整理为 JSON 格式：

{
  "name": "张三",
  "age": 28,
  "skills": ["Python", "JavaScript"]
}
```

## 高级提示词技术

### 少样本提示（Few-Shot Prompting）

提供少量示例，让模型学习模式：

```
将中文成语翻译成英文，保持简洁：

画蛇添足 → Gilding the lily
对牛弹琴 → Casting pearls before swine
亡羊补牢 → Better late than never

杯弓蛇影 →
```

### 思维链（Chain-of-Thought, CoT）

引导模型展示推理过程：

```
问题：一个农场有鸡和兔共 35 只，脚共 94 只。鸡和兔各有多少只？

请逐步推理：
1. 假设全是鸡，应该有 35 × 2 = 70 只脚
2. 实际多了 94 - 70 = 24 只脚
3. 每只兔比鸡多 2 只脚
4. 所以兔有 24 ÷ 2 = 12 只
5. 鸡有 35 - 12 = 23 只

答案：鸡 23 只，兔 12 只
```

### 零样本思维链（Zero-Shot CoT）

不给出示例，仅通过提示词触发推理：

```
问题：15 × 24 = ?

让我们一步步思考：
```

### 自我一致性（Self-Consistency）

让模型生成多个推理路径，选择最一致的答案：

```
问题：[复杂问题]

请从 3 个不同角度分析这个问题，然后综合得出最终答案。
```

### 反思与修正（Reflection & Refinement）

让模型自我检查和修正：

```
请回答以下问题，然后检查你的答案：

[问题]

回答：

检查：
- 逻辑是否正确？
- 计算是否有误？
- 是否遗漏了重要信息？

修正后的回答：
```

### ReAct（Reasoning + Acting）

结合推理和行动，适用于 Agent 场景：

```
你需要回答用户的问题。你可以使用以下工具：
- search(query)：搜索互联网
- calculator(expression)：计算数学表达式

请按照以下格式思考：
Thought: [你的思考]
Action: [工具名称]([参数])
Observation: [工具返回的结果]
...（重复 Thought/Action/Observation）
Final Answer: [最终答案]

问题：2024 年诺贝尔物理学奖得主是谁？
```

### 提示词链（Prompt Chaining）

将复杂任务拆分为多个提示词，串联执行：

```
# 第一步：提取关键信息
从以下文本中提取所有日期和事件：
[长文本]

# 第二步：整理为时间线
将上一步提取的信息整理为时间线格式：
[第一步的输出]

# 第三步：生成摘要
基于时间线生成 100 字摘要：
[第二步的输出]
```

## 常见任务模式

### 文本分类

```
请将以下评论分类为：正面 / 负面 / 中性

评论："这个产品的质量超出预期，物流也很快！"
分类：
```

### 信息提取

```
请从以下文本中提取：
- 人名
- 地名
- 时间
- 事件

文本：[输入文本]

输出 JSON 格式：
{
  "people": [],
  "locations": [],
  "times": [],
  "events": []
}
```

### 文本改写

```
请将以下文本改写为更正式的商务邮件语气：

原文："嘿，你上次说的那个方案我看了，挺好的，咱们可以开始搞了。"

要求：
- 使用正式称谓
- 明确表达同意
- 提出下一步行动计划
```

### 代码生成

```
请用 Python 编写一个函数，实现以下功能：
- 输入：一个整数列表
- 输出：列表中所有偶数的和
- 要求：时间复杂度 O(n)，空间复杂度 O(1)
- 包含类型提示和文档字符串
```

### 创意写作

```
请创作一个科幻微小说，要求：
- 主题：人工智能与人类情感
- 字数：300-400 字
- 风格：略带忧伤的温情
- 必须包含一个意想不到的转折
```

## 提示词优化技巧

### 迭代优化

1. 编写初始提示词
2. 测试输出
3. 分析不足之处
4. 调整提示词
5. 重复直到满意

### A/B 测试

对同一任务使用不同提示词，比较效果：
- 测试不同角色设定
- 测试不同示例数量
- 测试不同输出格式

### 负面提示（Negative Prompting）

明确告诉模型不要做什么：

```
请总结以下文章，要求：
- 不要复制原文的句子
- 不要添加个人观点或评论
- 不要遗漏任何关键数据
```

### 温度参数（Temperature）

调整模型的创造性程度：
- **Temperature = 0**：确定性输出，适合代码、数据提取
- **Temperature = 0.7**：平衡，适合一般任务
- **Temperature = 1.0+**：高创造性，适合创意写作、头脑风暴

## 常见问题与解决

### 模型不遵循格式

解决：在提示词中提供更详细的格式说明和示例

### 输出过长或过短

解决：明确指定字数或 Token 数量限制

### 模型产生幻觉

解决：
- 提供足够的上下文
- 要求模型基于给定信息回答
- 添加"如果不确定，请说明"的指令

### 偏见问题

解决：
- 在提示词中要求客观中立
- 提供多角度的示例
- 审查输出中的潜在偏见

## 最佳实践总结

1. **从清晰的角色定义开始**
2. **使用具体的任务描述**
3. **提供充分的上下文**
4. **给出期望输出的示例**
5. **明确格式和约束条件**
6. **分解复杂任务**
7. **使用分隔符组织内容**
8. **迭代测试和优化**
9. **记录有效的提示词模板**
10. **考虑模型的能力和局限**
