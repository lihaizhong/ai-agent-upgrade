# RAG 系统架构详解

检索增强生成（Retrieval-Augmented Generation, RAG）是一种将信息检索与文本生成相结合的技术框架。它通过从外部知识库中检索相关信息来增强大语言模型（LLM）的回答能力，解决 LLM 的知识时效性和幻觉问题。

## RAG 的核心思想

传统 LLM 的知识来自于预训练数据，存在两个主要问题：

1. **知识截止（Knowledge Cutoff）**：模型只能知道训练数据中的信息，无法获取最新知识
2. **幻觉（Hallucination）**：模型可能会编造看似合理但实际错误的信息

RAG 的解决方案是：在生成回答之前，先从外部知识库中检索相关文档，然后将这些文档作为上下文提供给 LLM，让模型基于检索到的真实信息生成回答。

## 离线处理流程

在系统上线前，需要对知识库进行预处理：

### 1. 数据采集

收集各种格式的文档：
- 结构化数据：数据库、表格、JSON
- 半结构化数据：Markdown、HTML、XML
- 非结构化数据：PDF、Word、纯文本
- 多模态数据：图片、视频（需要额外处理）

### 2. 文档解析

将不同格式的文档转换为统一的文本表示：
- PDF 解析：处理扫描件（需要 OCR）、提取文本和表格
- HTML 解析：去除标签，提取正文
- 表格处理：将表格转换为文本描述或结构化表示
- 图片处理：使用视觉模型生成描述

### 3. 文本分块（Chunking）

将长文档切分为适合检索和处理的片段：

**分块策略**：
- **固定长度分块**：按字符数或 Token 数切分，简单高效
- **语义分块**：按句子或段落边界切分，保持语义完整性
- **递归分块**：先按大段落切分，再递归细分为小片段
- **基于结构的分块**：利用文档的标题、段落等结构信息

**重叠设置**：
相邻分块之间保留一定重叠（如 50-100 字符），避免关键信息被分割到两个块中。

**最佳实践**：
- 分块大小通常在 200-500 个 Token 之间
- 根据内容类型调整分块策略（代码、论文、对话等）
- 保留分块的元数据（来源、位置、时间等）

### 4. 向量化（Embedding）

将文本分块转换为高维向量：

**选择 Embedding 模型**：
- OpenAI text-embedding-ada-002/text-embedding-3
- BGE（BAAI General Embedding）
- GTE（General Text Embedding）
- E5（EmbEddings from bidirEctional Encoder rEpresentations）
- M3E（Moka Massive Mixed Embedding）

**考虑因素**：
- 向量维度：768、1024、1536 等
- 支持的语言：中文、英文、多语言
- 上下文长度：能处理的最大文本长度
- 性能与质量的权衡

### 5. 索引构建

将向量存储到向量数据库中，构建高效索引：

- **平面索引（Flat）**：精确搜索，适合小规模数据
- **IVF（倒排文件索引）**：基于聚类的近似搜索
- **HNSW（分层可导航小世界）**：基于图的快速搜索
- **PQ（乘积量化）**：压缩向量，节省内存
- **混合索引**：结合多种技术

## 在线检索流程

### 查询处理

1. **查询理解**：识别用户意图和查询类型
2. **查询扩展**：使用同义词、相关词扩展查询
3. **查询改写**：将自然语言查询转换为更适合检索的形式
4. **多查询生成**：生成多个相关查询，提高召回率

### 检索策略

#### 稀疏检索（Sparse Retrieval）

基于关键词的检索方法：
- **BM25**：经典的词袋模型排序算法
- **TF-IDF**：词频-逆文档频率
- **优势**：精确匹配效果好，可解释性强
- **劣势**：无法捕捉语义相似性

#### 密集检索（Dense Retrieval）

基于向量相似度的检索：
- 将查询转换为向量
- 在向量空间中搜索最相似的文档向量
- **优势**：语义理解能力强，支持跨语言检索
- **劣势**：对罕见词和专有名词效果可能不佳

#### 混合检索（Hybrid Retrieval）

结合稀疏和密集检索：
- 分别进行关键词检索和向量检索
- 使用 RRF（Reciprocal Rank Fusion）或加权融合结果
- **优势**：兼顾精确匹配和语义理解
- **实践**：通常比单一方法效果更好

### 重排序（Reranking）

初步检索后，使用更精确的模型对结果重新排序：

**交叉编码器（Cross-Encoder）**：
- 将查询和文档拼接后输入模型
- 直接输出相关性分数
- 精度高但计算成本高
- 代表：BGE-Reranker、Cohere Rerank

**重排序策略**：
- 对前 K 个结果进行重排序
- 结合多样性、时效性、权威性等因素
- 使用学习排序（Learning to Rank）模型

## 提示工程与生成

### 上下文组装

将检索到的文档组织成 LLM 可以理解的格式：

```
基于以下参考资料回答问题：

[文档 1]
标题：xxx
内容：xxx
来源：xxx

[文档 2]
标题：xxx
内容：xxx
来源：xxx

---

问题：用户的原始问题
```

### 提示设计原则

1. **清晰指令**：明确告诉模型做什么
2. **角色设定**：让模型扮演专家角色
3. **格式要求**：指定输出格式（JSON、列表等）
4. **约束条件**：限制回答长度、风格等
5. **引用要求**：要求模型标注信息来源
6. **不确定处理**：要求模型在不确定时说明

### 引用与归因

高质量 RAG 系统应该能够：
- 标注回答中每条信息的来源文档
- 支持用户点击查看原始文档
- 在多个来源冲突时进行说明

## RAG 的高级技术

### 自适应 RAG（Adaptive RAG）

根据查询复杂度动态选择检索策略：
- 简单查询：直接使用 LLM 回答
- 中等查询：单次检索
- 复杂查询：多步检索和推理

### 迭代检索（Iterative Retrieval）

多轮检索，逐步细化：
1. 初始检索获取初步信息
2. 分析初步信息，生成新的检索查询
3. 重复直到获得足够信息

### 图 RAG（Graph RAG）

将知识组织为图结构：
- 实体抽取和链接
- 关系建模
- 图遍历检索
- 社区发现和摘要

### 多模态 RAG

支持多种数据类型：
- 文本 + 图像检索
- 音频和视频处理
- 跨模态对齐

### Agentic RAG

结合 AI Agent 能力：
- 工具调用（搜索、计算、API）
- 规划和推理
- 自我修正和验证
- 多 Agent 协作

## 评估与优化

### 评估指标

**检索质量**：
- 召回率（Recall）：相关文档被检索到的比例
- 精确率（Precision）：检索结果中相关文档的比例
- MRR（Mean Reciprocal Rank）：首个相关文档的排名倒数均值
- NDCG（Normalized Discounted Cumulative Gain）：考虑排序质量的指标

**生成质量**：
- 忠实度（Faithfulness）：回答是否与检索文档一致
- 答案相关性（Answer Relevance）：回答是否针对问题
- 上下文精确率（Context Precision）：检索上下文的质量
- 上下文召回率（Context Recall）：是否检索到足够信息

### 评估方法

1. **人工评估**：最准确但成本高
2. **LLM 作为评判者**：使用 GPT-4 等模型自动评估
3. **端到端测试**：构建测试集，自动运行并评分

### 常见优化方向

1. **查询优化**：查询重写、扩展、分解
2. **文档处理**：更好的解析、分块、清洗
3. **Embedding 优化**：微调 Embedding 模型、领域适配
4. **检索优化**：混合搜索、重排序、过滤
5. **生成优化**：提示优化、模型选择、后处理
6. **缓存优化**：常见查询缓存、Embedding 缓存

## 实际部署建议

### 架构选型

- **小型项目**：LangChain/LlamaIndex + Chroma/Pinecone
- **中型项目**：自托管 Milvus/Qdrant + FastAPI
- **大型项目**：分布式 Milvus + 微服务架构

### 成本控制

- Embedding 调用是主要成本之一，考虑批处理和缓存
- 向量数据库的选择影响存储和查询成本
- LLM 调用优化：提示压缩、结果缓存、模型选择

### 可观测性

- 记录每次检索的查询、结果和延迟
- 监控检索质量和生成质量指标
- 设置告警，及时发现异常

### 安全与隐私

- 敏感数据脱敏或加密
- 访问控制和权限管理
- 数据隔离（多租户场景）
